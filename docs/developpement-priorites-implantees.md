# تطوير الأولويات المدمجة في المشروع (حالة التنفيذ)

هذا المستند يلخص الأفكار ذات الأولوية التي تم **تضمينها وتطويرها** داخل النموذج (`backend` + الواجهة) وفق خارطة الأولويات.

## 1) بطاقات التغذية الراجعة — دورة حياة (أولوية عالية)
**ما تم تضمينه:**
- نموذج بيانات موسّع: `status` (proposed/approved/rejected/in_progress/completed)، `assignee`, `reviewNotes`, `actions`, `history`, `updatedAt/updatedBy`.
- واجهات خلفية:
  - `GET /api/admin/feedback-cards?studentId=` و `GET /api/teacher/feedback-cards?studentId=`
  - `POST /api/admin/feedback-cards/update` و `POST /api/teacher/feedback-cards/update` (تحديث الحالة/ملاحظات/موعد مراجعة/إجراءات) مع **سجل تدقيق** وتاريخ تغييرات.
- الواجهة (المساعد الاجتماعي وبيئة الوكلاء): عرض البطاقات مع الحالة والأولوية والأدلة وموعد المراجعة، وأزرار اعتماد/تنفيذ/رفض عند تسجيل الدخول بصلاحية (إدارة أو معلم ضمن النطاق) مع تحديث فوري.

**المتبقي لاحقًا:** ربط تلقائي بالمهام/الخطط، واجهة تعديل تفصيلي للتوصيات والموارد، وإشعارات استحقاق.

## 2) إدارة الحالات — تتبع زمني (أولوية عالية)
**ما تم تضمينه:**
- نموذج بيانات موسّع للحالات: `ownerId`, `nextReview`, وخط زمني (`timeline`) يتضمن `by/type`.
- واجهات خلفية:
  - `GET /api/admin/cases` و `GET /api/teacher/cases`
  - `POST /api/admin/cases/update` (تحديث الحالة/المالك/التركيز/موعد مراجعة)
  - `POST /api/admin/cases/timeline` و `POST /api/teacher/cases/timeline` (إضافة حدث زمني) مع **سجل تدقيق**.
- الواجهة: عرض الحالات النشطة وآخر حدث وموعد المتابعة مع إمكانية إضافة حدث للحالة عند توفر جلسة مصادقة.

**المتبقي لاحقًا:** عرض تفصيلي لكل حالة، مراحل/حالات متعددة، تنبيهات مواعيد إعادة التقييم، وربط أعمق بالفصول والسنة.

## 3) توحيد نموذج الكفايات (أولوية عالية)
**ما تم تضمينه:**
- مرجع كفايات منظم حسب المستوى/المادة: `competencyReferences` في `data.json` (مهارة، وصف، مؤشرات، عتبة إتقان مستهدفة).
- واجهات: `GET /api/admin/competency-refs?level=` و `GET /api/teacher/competency-refs?level=`.
- مواءمة التحليلات: `computeStudentInsights` يرفق الكفايات المعيارية (`competenciesAligned`, `competencyRefs`) ويقارن الإتقان بالهدف المرجعي في التقارير.

**المتبقي لاحقًا:** تغطية جميع المستويات/المواد، ربط التقييمات والواجبات بالمؤشرات، ولوحة تحرير مرجعية.

## 4) ربط الواجهة بالخلفية (API-first) مع فصل البوابات (أولوية عالية)
**ما تم تضمينه:**
- جلسة مصادقة في الواجهة: استدعاء `POST /api/auth/login` مع `portal`، حفظ token والمستخدم، وإرسال `Authorization` للطلبات.
- تحميل حي لعرض **المساعد الاجتماعي وبيئة الوكلاء** من `/api/admin/smart-assistant` مع **تراجع تجريبي (fallback)** عند غياب الخادم.
- إجراءات تفاعلية (اعتماد بطاقة، إضافة حدث حالة) مرتبطة بالـ API مع رسائل حالة وتحديث العرض.
- الحفاظ على فصل البوابات: بيانات وإجراءات الإدارة عبر بوابة الإدارة؛ نطاق المعلم مقيد بفصوله في واجهات المعلم.

**المتبقي لاحقًا:** تعميم الربط الحي لباقي الشاشات (تقارير/رؤى/لوحات)، تخزين جلسة آمن، وتجديد/انتهاء صلاحية الرمز.

## 5) تقوية الخصوصية والأمن (أولوية عالية — تدريجي/متقدم في النموذج)
**ما تم تضمينه:**
- فصل بوابات وصلاحيات ونطاق وصول (RBAC/scope) في المسارات الجديدة والحية.
- تدقيق موسّع للإجراءات الحساسة: قراءة/تحديث البطاقات، تحديث الحالات، الخط الزمني، تقييمات، تواصل، سياسات احتفاظ.
- **تحصين مصادقة (نموذج):** تجزئة كلمات المرور PBKDF2، ترقية تلقائية، رموز وصول قصيرة الأمد + **Refresh Token** مع تدوير (`/api/auth/refresh`).
- **احتفاظ:** `retentionPolicy` وواجهات `GET/POST /api/admin/retention*` لتطبيق تنظيف وفق السياسة.

**المتبقي للإنتاج:** HTTPS إلزامي وإدارة أسرار، قاعدة بيانات حقيقية ونسخ احتياطي مشفر، سياسات حذف/إخفاء هوية كاملة، تحديد معدل محاولات ومراقبة أمنية.

## إضافات مكتملة في هذه الجولة
- **مرجع كفايات شامل** لكل المستويات والمواد + بنية `assessments` (تقييمات إدخال/تشخيصية) وواجهات إدارتها.
- **ربط حي موسّع** للوحات والتقارير والأداء وتحليلات التعلم ورؤى المعلم/ولي/تلميذ مع إدارة تفصيلية للبطاقات والحالات.
- **قياس أثر وتنبيهات استحقاق** (`/api/admin/impact`, `/api/admin/alerts`, `/api/teacher/alerts`) وسجل `impactLog`.
- **تواصل أسري تنفيذي محكوم** (مسودة→اعتماد→إرسال) عبر `communications` مع حوكمة وتدقيق.

راجع أيضًا: `docs/production-gouvernance-roadmap.md`.

## تشغيل وتجربة
```bash
cd ryad-alaqsa-app/backend
node server.js
# افتح http://localhost:3001
```
حسابات تجريبية (كلمة المرور `1234`): `director@ryad.ma`, `supervisor@ryad.ma`, `admin@ryad.ma`, `teacher@ryad.ma` وغيرها في `backend/data.json`.

**مسار تجربة الأولويات:** دخول بوابة الإدارة → **المساعد الاجتماعي وبيئة الوكلاء** → اعتماد/تحديث بطاقة تغذية راجعة أو إضافة حدث لحالة وملاحظة انعكاس البيانات والتدقيق.

## مبادئ محفوظة
- قرار ومراجعة بشرية للمخرجات المؤثرة.
- خصوصية، تقليل بيانات، وفصل سياقات.
- إنصاف وعدم وصم، دعم وإثراء معًا.
- قابلية التتبع بالأدلة وسجل التدقيق.
