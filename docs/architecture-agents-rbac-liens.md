# معمارية الوكلاء، الربط البنيوي/الإحصائي، والصلاحيات
**الهدف:** تحويل الرؤى القاعدية إلى منظومة وكلاء مساندة مع أدلة وتدقيق، وتفعيل المساعد الاجتماعي الذكي، وتعزيز أدوات المعلم — ضمن فصل بوابات وRBAC ونطاق.

---

## 1) مكونات المنظومة (ربط بنيوي)

```text
[بوابة الإدارة - خادم رئيسي]                 [فضاءات خاصة]
  مدير/نائب/مشرف/إدارة/كاتب                  معلم / ولي أمر / تلميذ
           │                                        │
           └────────────── API آمن (Token) ─────────┘
                               │
                    [Auth + Portal Guard]
                               │
                    [RBAC + Scope Resolver]
                               │
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
 [Data Core]            [Agent Orchestrator]    [Audit & Evidence]
  تلاميذ/مستويات          تشخيص/مسار/مواهب/       سجل عمليات + أدلة
  حضور/واجبات/درجات       تغذية راجعة/تواصل        مرتبطة بالمخرجات
  كفايات/مواهب/مسارات     (قواعد → وكلاء)          وقابلة للاستعراض
  أنشطة/مناهج/مكتبة               │
        └──────────┬─────────────┘
                   ▼
        [Insights & Actions Layer]
          تقارير ملخص/موسّع، تنبيهات،
          توصيات، مسودات تواصل، خطط،
          تحليلات فردية/جماعية
```

**الربط البنيوي (علاقات مفتاحية):**
- `student ← attendance, assignments/submissions, grades, competencies, talents, learningPath, interventions, activities`
- `insight/report ← evidence[] ← (competencies/grades/attendance/profile/agentRuns)`
- `agentRun → evidence → recommendation/alert/draft/plan` (قابلية تتبع)
- `user(role, scope) → permitted resources` (فصل بوابة + نطاق: global/levels/classes/children/student)

## 2) من رؤى قاعدية إلى وكلاء متخصصين (تطور تدريجي)
| المرحلة | الآلية | المخرجات | الضبط |
|---|---|---|---|
| **الحالية (منفذة كنموذج)** | محرك قواعدي يحلل بيانات ويولّد رؤى/تنبيهات/توصيات | تصنيف، فجوات/قوة، مسار، تمارين، أنشطة، تقرير ملخص/موسّع | RBAC+نطاق، تدقيق، ربط أدلة أساسي |
| **المرحلة 2** | وكلاء متخصصون (تشخيص، مسار، مواهب، تغذية راجعة، تواصل) مع تشغيل مُسجّل | `agentRuns` + `evidence` لكل مخرج، مسودات قابلة للاعتماد | مراجعة بشرية إلزامية، سجل تدقيق موسّع |
| **المرحلة 3** | تنسيق بين الوكلاء وسير عمل (تشخيص→خطة→تواصل→متابعة→إعادة تقييم) | مهام مجدولة (جلسات استماع، إعادة تقييم)، قياس أثر | موافقات حسب الدور، سياسات خصوصية |

**قاعدة:** كل توصية/تنبيه يجب أن يحيل إلى **أدلة** (بيانات مصدر) وأن يكون قابلاً للمراجعة والإبطال.

## 3) سجل الأدلة والتدقيق (Evidence & Audit)
- **Evidence:** `{id, agentRunId, studentId, type, ref, weight}` — يربط المخرج بالمدخل.
- **Audit log (موسّع):** `{actor, role, action, entityType, entityId, details, at}` + (مقترح إنتاجيًا: `portal, scope, ip, result, evidenceIds`).
- **أحداث تُدقّق:** تسجيل دخول، قراءة تقارير/رؤى حساسة، إنشاء/تعديل/اعتماد خطط ومسودات، تصدير، تغييرات صلاحيات.
- **الوصول للسجلات:** مدير/نائب/إدارة (حسب السياسة) ضمن منصة الإدارة.

## 4) الربط الإحصائي والتحليلي (حسب الصلاحية والنطاق)

| المستوى | مؤشرات/تحليلات | من يراها | مثال ربط |
|---|---|---|---|
| **تلميذ** | تقدم فردي، كفايات، حضور، مسار، توصيات | تلميذ (ذاته)، ولي (أبناؤه)، معلم (فصوله) | `student → competencies/grades/attendance → insight` |
| **فصل/قسم** | توزيع مستويات، فجوات شائعة، إنجاز واجبات، انضباط | معلم (فصوله)، مشرف/إدارة (نطاقهم) | تجميع Scoped على `classId` |
| **مستوى/مؤسسة** | نسب دعم/تميز، فعالية برامج، حضور وأداء | مشرف/إدارة/نائب/مدير | تجميع هرمي `level → classes → students` |
| **استراتيجي** | أهداف، أداء تشغيلي، مالي، أثر مبادرات | مدير/نائب (ومحدود للإدارة) | ربط `goals/strategy` بمؤشرات تعلم وتشغيل |

**آليات:**
- **تجميع هرمي:** فرد ← فصل ← مستوى ← مؤسسة مع احترام النطاق.
- **مؤشرات مشتقة:** إتقان كفاية، خطر تعثر، تميز، التزام إعادة تقييم، أثر تدخل (قبل/بعد).
- **تصفية إلزامية:** كل استعلام يمر عبر `scope filter` قبل الإرجاع.

## 5) المساعد الاجتماعي وبيئة الوكلاء (فصل أدوار واضح)
- **المساعد الاجتماعي (دور/وظيفة إنسانية مهنية):** متدخل تربوي واجتماعي ونفسي للتلميذ؛ يربط السياقات (أكاديمي، اجتماعي، نفسي، أسري ضمن الحدود المهنية)، يهيئ المناخ ويوحّد الرؤى بين الفاعلين، ويتابع الحالات **حالة بحالة** عبر الفصول والسنة الدراسية لتحقيق الأهداف.
- **بيئة الوكلاء (أدوات مساندة):** بنية مساعدة لتسهيل أداء المهام (استخلاص، تتبع، تنبيهات، مسودات، اقتراح مسارات/أنشطة) مع ربط الأدلة والتدقيق؛ **لا تستبدل** التدخل البشري ولا القرار النهائي.
- **الوصول:** منصة الإدارة (مدير، نائب، مشرف، إدارة) مع صلاحيات تفاضلية.
- **المكتبة العلمية:** موارد مصنفة (بيداغوجيا، علم نفس تربوي، تقييم، تواصل) قابلة للربط بالتوصيات.
- **مخرجات مشتركة:** تقارير ملخصة/موسعة، خطط متابعة، مسودات تواصل، سجلات أدلة وتتبع زمني.
- **API (نموذج):** `/api/admin/smart-assistant`, `/api/admin/library`, `/api/admin/system-stats`.

## 6) تعزيز واجهة المعلم (تقارير ومسودات)
- **ملخص تنفيذي:** خلاصة، نقاط رئيسية، خطوات تالية (سريع الفهم).
- **تقرير موسّع:** كفايات، أدلة، منهجية، تاريخ بيانات، مخرجات الوكلاء.
- **مسودات تواصل:** رسائل للأسر/تغذية راجعة للتلميذ مولدة كمساعدة، قابلة للتعديل و**تتطلب اعتمادًا** قبل الإرسال.
- **ربط بالإجراءات:** اعتماد خطة، جدولة إعادة تقييم/جلسة استماع، إشعار ولي الأمر — مع تدقيق.

## 7) أدوات وآليات تشغيل المنظومة
- **خط أنابيب البيانات:** جمع (حضور/واجبات/درجات/ملاحظات/أنشطة) → تطبيع → تحليل كفايات → توليد رؤى/أدلة → تنبيه/توصية → مراجعة بشرية → تنفيذ → إعادة تقييم.
- **محرك قواعد/وكلاء:** قواعد عتبات وإشارات (قابلة للتهيئة) كأساس، مع طبقة وكلاء لتنسيق المهام والتوليد.
- **إدارة المهام:** ربط التنبيهات بخطط ومهام (مسؤول، موعد، حالة).
- **حوكمة:** صلاحيات، تفويض، موافقات، سجل تدقيق، وسياسات احتفاظ/خصوصية.
- **قابلية التوسع:** استبدال `data.json` بـ PostgreSQL، طوابير للمهام الدورية، تكامل إشعارات (داخل التطبيق/بريد/واتساب وفق سياسة).
