# اتفاقيات API — Ryad Al Aqsa

مرجع موحّد لتصميم نقاط النهاية في `apps/api` (Fastify) بما يضمن الاتساق، الأداء، والأمان.

## 1) الإصدارات (Versioning)

- المسار الحالي: `/api/...` (توافق مع النموذج الأولي).
- المسار الإنتاجي المستهدف: `/api/v1/...`.
- عند إدخال `v1`: يُبقى `/api` كـ alias لفترة انتقالية (Deprecation header: `Sunset`).
- التغييرات غير المتوافقة تستلزم إصدارًا جديدًا؛ الإضافات المتوافقة تمر داخل نفس الإصدار.

## 2) صيغة الاستجابة

**نجاح:**
```json
{ "ok": true, "data": { }, "meta": { "page": 1, "pageSize": 20, "total": 137 } }
```

**خطأ:**
```json
{ "ok": false, "error": "validation_error", "message": "حقل غير صالح", "details": [{ "path": "score", "message": "max 20" }] }
```

رموز الأخطاء المعتمدة: `unauthorized` (401)، `forbidden` (403)، `not_found` (404)، `conflict` (409)، `validation_error` (400)، `rate_limited` (429)، `internal_error` (500).

## 3) الترقيم والصفحات (Pagination)

- المدخلات: `?page=1&pageSize=20` (حد أقصى 100) أو cursor للمجموعات الكبيرة: `?cursor=<opaque>&limit=50`.
- الاستجابة تحمل `meta.total` عند توفره، و`meta.nextCursor` للـ cursor.
- الترتيب الافتراضي ثابت (`createdAt desc` أو `id asc`) لتجنّب تقلّب النتائج.

## 4) الفلترة والبحث

- أسماء معاملات موحّدة: `levelId`, `classId`, `subjectId`, `studentId`, `status`, `term`, `from`, `to`, `q`.
- `q` بحث نصي مع حد أدنى حرفين وحد أقصى 100 حرف.
- كل فلتر يُتحقق منه بـ Zod ويُقيّد بالنطاق (Scope) قبل الوصول لقاعدة البيانات.

## 5) الأداء

- **تجنّب N+1:** استخدام `include/select` في Prisma بحقول محددة فقط.
- **فهارس إلزامية:** `(studentId, createdAt)`، `(classId, date)`، `(status, nextReview)`، `(levelName, subject)`.
- **كاش Redis** للقراءات الثقيلة (لوحة القيادة، التحليلات) مع TTL 30–120 ثانية و`ETag`.
- **حدود الاستجابة:** لا تُرجع أكثر من 100 عنصر أو 1MB في طلب واحد.
- **الحسابات الثقيلة** (تقارير الأثر، ML) تُنفّذ في طابور خلفي وتُخزّن نتائجها.

## 6) الأمان

- `Authorization: Bearer <accessToken>` لكل مسار غير عام.
- التحقق من البوابة (`admin_portal` / `private`) قبل التحقق من الدور.
- التحقق من النطاق لكل كيان (فصل، تلميذ، ولي).
- حد معدل: 200/دقيقة عام، 10/دقيقة لـ `/auth/login` و`/auth/refresh`.
- تدقيق إلزامي لكل `POST/PATCH/DELETE` حساس مع `actorId` و`entityType/entityId`.
- لا تُسجّل كلمات المرور أو الرموز أو بيانات صحية خام في السجلات.

## 7) العمليات الكتابية (Idempotency)

- نقاط الإنشاء الحساسة (تواصل، اعتماد، تسجيل نشاط) تقبل `Idempotency-Key`.
- إعادة الطلب بنفس المفتاح تُرجع نفس النتيجة دون تكرار.
- قيود فريدة في قاعدة البيانات تمنع التكرار (مثال: `(studentId, activityId)`).

## 8) التواريخ والأرقام

- التواريخ ISO 8601 بتوقيت UTC (`2026-11-18T10:15:00.000Z`).
- الدرجات: `/20` افتراضيًا مع حقل `scale` عند الحاجة.
- العملة: `MAD` مع تخزين بالدرهم (عدد صحيح أو عشري بدقة 2).

## 9) الإصدار والتوثيق

- `apps/api/openapi.json` يُولّد من المخططات (Zod → JSON Schema) ويُحدّث مع كل تغيير.
- كل نقطة نهاية تحمل: الوصف، الأدوار المسموحة، أمثلة الطلب/الاستجابة، وأكواد الخطأ.
- اختبار عقد (contract test) يفشل إذا تغيّرت استجابة قائمة دون تحديث التوثيق.

## 10) قائمة مراجعة قبل الدمج

- [ ] Zod schema للمدخلات + أنواع الاستجابة.
- [ ] فحص البوابة + الدور + النطاق.
- [ ] تدقيق للعملية.
- [ ] فهرس مناسب لأي استعلام جديد.
- [ ] اختبار وحدة + اختبار تكامل.
- [ ] تحديث OpenAPI و`docs/api-reference.md`.
