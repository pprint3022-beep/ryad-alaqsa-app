# خارطة الطريق الإنتاجية والحوكمة (تقدم تنفيذي)

## 1) تشفير كلمات المرور وتحصين الجلسات
- **منفّذ (النموذج):** تجزئة كلمات المرور بـ PBKDF2-SHA256 (`pbkdf2$iter$salt$hash`) مع ترقية تلقائية عند تسجيل الدخول للحسابات القديمة (نموذج أولي)، ومقارنة آمنة.
- **منفّذ:** رمز وصول قصير الأمد (Access JWT) + **رمز تحديث** (`/api/auth/refresh`) مع تدوير وتخزين جلسات في `sessions` وسياسة انتهاء.
- **إنتاج:** نقل الأسرار إلى متغيرات بيئة/مدير أسرار، إجبار HTTPS، ملفات تعريف ارتباط آمنة/HttpOnly إن استُخدمت، تحديد معدل المحاولات، وقفل/تنبيه عند محاولات مشبوهة.

## 2) HTTPS، قاعدة بيانات حقيقية، واحتفاظ/حذف
- **منفّذ (تهيئة في النموذج):** سياسة احتفاظ (`retentionPolicy`) في البيانات، نقاط `GET /api/admin/retention` و`POST /api/admin/retention/apply` (تنظيف تدقيق/جلسات وفق السياسة) مع تدقيق.
- **تخزين حالي:** ملف `backend/data.json` (ملائم للنموذج) — موثق كمرحلة انتقالية.
- **إنتاج (مطلوب):**
  - قاعدة بيانات حقيقية (مثل PostgreSQL) مع مخطط للجداول (مستخدمون/أدوار/نطاق، تلاميذ، كفايات مرجعية وتقييمات، بطاقات تغذية راجعة وتاريخ، حالات وخط زمني، تواصل، أدلة، تدقيق).
  - HTTPS عبر عاكس/خادم (TLS)، نسخ احتياطي مشفر، فصل بيئات (تطوير/إنتاج).
  - سياسات احتفاظ/حذف/إخفاء هوية للتحليلات، وحق الوصول/التصحيح وفق السياسة المؤسسية والقانونية.

## 3) توسيع نموذج الكفايات وربطه بتقييمات الإدخال
- **منفّذ:** توسيع `competencyReferences` ليغطي **جميع المستويات (تمهيدي–السادس)** ومعظم المواد/المجالات (لغات، رياضيات، علوم، تربية إسلامية، تاريخ وجغرافيا، ثقافة، فنون، بدنية...) مع مؤشرات وعتبات إتقان.
- **منفّذ:** بنية `assessments` (تقييمات إدخال/تشخيصية/تكوينية) مرتبطة بالتلميذ والمهارة/المادة/المستوى والأدلة (`/api/admin/assessments`, `/api/teacher/assessments`).
- **منفّذ:** مواءمة الرؤى/التشخيص مع المرجع (`competenciesAligned`, `targetMastery`) في التقارير والمسارات.
- **لاحقًا:** تغطية أدق لكل درس/وحدة، نماذج إدخال تقييم في الواجهة لكل دور، وربط تلقائي للتقييم بالبطاقات والمسارات.

## 4) تعميم الربط الحي بالشاشات وإدارة تفصيلية
- **منفّذ (حي مع fallback):** لوحة القيادة والتقارير والأداء وتحليلات التعلم (إدارة)، تقارير المعلم ورؤى/تشخيص التلاميذ وبطاقات ضمن النطاق، رؤى ولي الأمر والتلميذ (مساري) عبر API.
- **منفّذ:** إدارة تفصيلية للبطاقات والحالات في واجهة المساعد الاجتماعي وبيئة الوكلاء (اختيار عنصر، اعتماد/تنفيذ/إنجاز/رفض، ملاحظات، خط زمني للأحداث).
- **لاحقًا:** تعميم الربط لجميع الشاشات التشغيلية، محررات كاملة (توصيات/موارد/إسناد)، وتنبيهات داخل التطبيق.

## 5) قياس الأثر وتنبيهات استحقاق إعادة التقييم
- **منفّذ:** `GET /api/admin/impact` و`GET /api/admin/alerts` و`GET /api/teacher/alerts` لحساب بطاقات/حالات/استحقاقات إعادة تقييم، وسجل أثر `impactLog` (خط أساس/هدف/حالي) وربطه بالواجهة.
- **منفّذ:** تنبيهات استحقاق من مسارات التعلم وبطاقات التغذية الراجعة ومواعيد الحالات.
- **لاحقًا:** مؤشرات قبل/بعد منهجية لكل تدخل، تقارير أثر دورية، ولوحات اتجاهات زمنية.

## 6) تكامل تواصل أسري تنفيذي ضمن الحوكمة
- **منفّذ:** نموذج `communications` مرتبط بالمسودات مع حالات (مسودة/معتمد/مرسل) وحوكمة (`requiresApproval`, `approvedBy`, موافقة/خصوصية) عبر `/api/admin/communications*` و`/api/teacher/communications*`.
- **منفّذ:** منع الإرسال دون اعتماد (حكم حوكمة في API) وتسجيل تدقيق للتحديثات.
- **لاحقًا:** قنوات إرسال فعلية (واتساب/بريد/إشعار) عبر مزودات معتمدة، قوالب متعددة اللغات، وتتبع التسليم/القراءة ضمن السياسة.
